# StudSovet Messenger Desktop

Самостоятельное настольное приложение Windows на Electron. Это **не PWA, не ярлык сайта и не вкладка браузера**: запускается отдельный процесс `StudSovet Messenger.exe`, открывает собственное окно и не показывает навигацию сайта. Внутри используется тот же экран мессенджера и тот же CSS/HTML/JS, поэтому оформление совпадает с веб-мессенджером StudSovet.

## Как устроено подключение

- Приложение спрашивает адрес сервера StudSovet при первом запуске.
- После проверки доступности сервера открывает только мессенджер. Страницы мессенджера в меню и интерфейсе сайта удалены; прямое открытие `/messenger` в обычном браузере возвращает 404.
- Клиентский экран разрешается только запросам Electron-оболочки с техническим заголовком приложения. Этот заголовок служит ограничителем интерфейса, а не заменой серверной авторизации.
- Для защиты от сохранения входа используется временная Chromium-сессия Electron (`temp:`). При полном закрытии приложения сессия уничтожается; при следующем запуске пользователь снова вводит логин и пароль.
- Вход выполняется существующей формой сервера с текущей авторизацией, включая Telegram-код и обязательную смену пароля, если они требуются аккаунту.
- Все права каналов, диалогов, сообщений и вложений по-прежнему проверяет сервер. Desktop-клиент не хранит пароли и не обходит ACL.
- Для нескольких сотрудников используется один общий сервер. Если приложение запускается на другом компьютере, укажите LAN-IP или домен сервера; `127.0.0.1` на каждом компьютере означает сам этот компьютер.

Сервер должен быть запущен и доступен по сети. Для локальной машины используйте адрес и порт, которые показывает консоль `python run.py` (например, `http://127.0.0.1:80` либо `http://127.0.0.1:5000`). Для подключения через интернет используйте HTTPS.

Если сотрудники подключаются с других компьютеров по локальной сети, на серверном ПК в `.env` нужно явно настроить `WEB_HOST=0.0.0.0` и `WEB_PORT` на нужный порт, перезапустить `python run.py` и разрешить этот порт во входящих правилах брандмауэра только для доверенной частной сети. На клиентских ПК в приложении нужно указать LAN-IP серверного компьютера, например `http://192.168.1.20:5000`. Не используйте HTTP через публичный интернет: для такого доступа нужен HTTPS reverse proxy.

## Запуск исходников на Windows

1. Установите Node.js LTS (включая npm).
2. Запустите из корня проекта `RUN_MESSENGER_DESKTOP.bat`.
3. При первом запуске npm установит Electron; затем появится окно настройки сервера.
4. Введите адрес сервера. Приложение проверит `/auth/login` и откроет окно мессенджера.
5. В мессенджере нажмите **«Включить уведомления»** и разрешите уведомления в настройках Windows.

## Создание установщика Windows

Запустите `desktop-app/BUILD_WINDOWS_INSTALLER.bat` на Windows-машине с Node.js LTS. После успешной сборки установщик появится в `desktop-app/release/StudSovet-Messenger-Setup-1.9.6.exe`.

Для сборки используются Electron 45.3.1 и electron-builder 26.18.1. Сборка установщика требует доступа к npm registry для загрузки зависимостей и бинарного runtime Electron.

## Системные уведомления

После включения уведомлений приложение опрашивает только доступный текущему пользователю поток `/staff-messenger/api/notifications` с интервалом 4 секунды. Новые сообщения доставляются в системный центр уведомлений Windows. Закрытие главного окна крестиком скрывает приложение в системный трей; процесс и получение уведомлений продолжаются. Для полного выхода используйте пункт «Выйти из приложения» в меню значка в трее. Временная сессия авторизации уничтожается вместе с процессом; при следующем запуске все пользователи, включая главного администратора, входят заново. Для автоматического запуска используйте пункт «Запускать вместе с Windows».

Если сервер недоступен, уведомления не могут поступать. Клиент не обещает доставку при выключенном компьютере, завершённом процессе приложения или отсутствии сети.

## Безопасность

- `nodeIntegration` выключен, `contextIsolation` включён, renderer sandbox включён.
- Preload публикует только небольшой фиксированный IPC API без доступа к файловой системе и Node.js из страницы.
- Навигация ограничена тем же сервером и путями авторизации/мессенджера. Переходы в страницы сайта блокируются; внешние HTTPS-ссылки открываются в браузере.
- Пароль не сохраняется приложением. Cookie авторизации живут только во временной сессии Electron и не переживают полный выход из приложения; адрес сервера и пользовательские настройки хранятся отдельно.


## Версия 1.9.1 — исправление Windows-иконки и усиление защиты

- `assets/messenger.ico` пересобран с размерами до 256x256 и 512x512 на основе исходной иконки StudSovet. Это устраняет ошибку electron-builder `Icon must be at least 256x256 pixels`.
- В Electron запрещены браузерные разрешения сайта, загрузки файлов из удалённой страницы, webview и небезопасный mixed content. `contextIsolation`, `sandbox`, `nodeIntegration: false` и `webSecurity: true` сохранены.
- DevTools доступны только при явном запуске с `--dev`.
- Серверный адрес по-прежнему может быть HTTP для локальной сети; для доступа через интернет обязательно настройте HTTPS.

Проверка и обновление зависимостей выполняются сценарием `BUILD_WINDOWS_INSTALLER.bat`; актуальные правила приведены в разделе «Проверка зависимостей перед выпуском». Не запускайте `npm audit fix --force`.

## Проверка зависимостей перед выпуском (v1.9.4)

Сборочный сценарий синхронизирует `package-lock.json` при смене версии проекта, устанавливает точное дерево через `npm ci`, проверяет ESM API `minimatch`, запускает полный `npm audit` и только после успешных проверок запускает electron-builder. При любой ошибке установщик не создаётся.

Для дерева сборочных зависимостей заданы npm `overrides`: `minimatch@11.0.8` задан как scoped override только для `app-builder-lib`, а `@electron/universal` закреплён на `3.0.4`. Такое ограничение не принуждает остальные независимые пакеты проекта переходить на новую major-версию minimatch. Сборочный сценарий печатает разрешённое дерево `npm ls`, выполняет полный `npm audit`, а затем проверяет совместимость реальной сборкой на Windows.

Если аудит остановится, сценарий сохранит `npm-audit-report.json` и `npm-security-dependency-tree.txt` в `desktop-app`. Передай оба файла вместе с полным выводом сборки для следующей проверки. Не запускай `npm audit fix --force`: он может заменить electron-builder несовместимой основной версией. Lock-файл создаётся/обновляется сценарием и затем используется `npm ci`.

Для подключения через интернет используйте HTTPS с действительным сертификатом. HTTP допустим только для локальной разработки/доверенной локальной сети и не защищает пароль или сообщения от перехвата в сети. Заголовок `X-StudSovet-Desktop` не является механизмом аутентификации: сервер обязан проверять пользовательскую сессию и права доступа самостоятельно.


### Исправление Windows BAT (v1.9.3)

В Windows команда `npm` обычно является пакетным файлом `npm.cmd`. Поэтому в `BUILD_WINDOWS_INSTALLER.bat` вызов версии npm выполняется через `call npm --version`; без `call` управление могло не вернуться в основной BAT-файл после вывода версии.


### Обновление безопасности зависимостей (v1.9.4)

- Добавлены npm overrides: `minimatch@11.0.8` и `@electron/universal@3.0.4`.
- Удалён автоматический `npm audit fix` из сборочного процесса: обновления теперь контролируются lock-файлом и явными версиями override.
- Lock-файл синхронизируется с новой версией проекта перед `npm ci`.
- Перед упаковкой проверяются дерево зависимостей через `npm ls` и полный `npm audit`; при неуспехе сборка блокируется.
- Диагностика сохраняется в `npm-audit-report.json` и `npm-security-dependency-tree.txt`.


### Исправление иконки Windows (v1.9.5)

В предыдущем архиве v1.9.4 файл `assets/messenger.ico` фактически содержал только изображение 64x64, несмотря на более раннее описание в документации. Поэтому electron-builder правильно остановил сборку с сообщением `Icon must be at least 256x256 pixels`. В v1.9.5 ICO повторно создан из исходного `assets/messenger.png` размером 256x256 и проверен: он содержит варианты 16, 24, 32, 48, 64, 128 и 256 пикселей. Настройка `build.win.icon` продолжает указывать на этот ICO. После распаковки обновления пересоздайте установщик через `BUILD_WINDOWS_INSTALLER.bat`; lock-файл синхронизируется сценарием автоматически.


### Фоновый режим и уменьшение журналов (v1.9.6)

- Закрытие главного окна теперь скрывает его в системный трей; приложение остаётся запущенным, временная сессия и опрос уведомлений продолжаются. Полный выход выполняется только через «Выйти из приложения» в меню трея/приложения.
- Частота опроса темы в Electron снижена с 250 мс до 15 секунд (примерно в 60 раз меньше запросов).
- Уровень access-log Werkzeug установлен на WARNING: успешные HTTP-запросы больше не засоряют консоль, а предупреждения 4xx и ошибки 5xx остаются видимыми.
